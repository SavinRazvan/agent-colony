# MCP config files

| File | Role |
|------|------|
| **`mcp.json.kit.example`** | Canonical kit-only fragment (`agent-colony-mcp` server) |
| **`mcp.json`** | Merged kit + optional `mcp.user.json` (regenerated by `health` / `mcp link` / `mcp seed`) |
| **`mcp.user.example.json`** | Template for external servers (copy to `mcp.user.json`, gitignored) |
| **`mcp.registry.yaml.example`** | Agent ↔ server mapping template (includes DeepWiki worksheet) |
| **`mcp.registry.yaml`** | Live registry — kit-dev commits **kit tier only**; consumers get DeepWiki seeded on activate |

Install with `--with-mcp-json` merges kit + user fragments via `mcp_manage.py` → `.cursor/mcp.json`.
Consumer activate (non–kit-dev) seeds DeepWiki into `mcp.user.json` + registry when missing.
Re-run: `python3 -m agent_colony mcp seed --deepwiki`. Skill: `/mcp-connect`.

**Kit-dev allowlist:** live registry stays kit-tier; CLI smoke/call still allow servers listed in
`mcp.registry.yaml.example` when those servers are present in merged `mcpServers` (typically via
gitignored `mcp.user.json`).

See [`.ai_infra/docs/operations/connect-external-mcp.md`](../.ai_infra/docs/operations/connect-external-mcp.md).
